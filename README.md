## Step 1: Synthetic Detector Framing

[`validation_demo.py`](./validation_demo.py) is the first step.

This is where the detector path is worked out. The script generates synthetic
target-band signals near `0.67 Hz`, runs the current detection stack against
them, and produces the visualization and metric outputs that define what the
search target looks like.

This step exists because the work needed a detector path before anything else
could be compared. It is where the repo moved from framing and intuition into
something executable.

Artifacts produced here include:

- `paradigm_shift_demonstration.png`
- `quantum_system_validation_metrics.txt`

Current synthetic detector statistics:

- detection rate: `100.0%`
- mean detected frequency: `0.66896 Hz`
- standard deviation: `0.01195 Hz`
- 95% confidence interval: `[0.64553, 0.69239] Hz`
- t-test against `0.67 Hz`: `t = -0.1740`
- p-value: `0.8703`

These statistics belong to the synthetic detector lane only. They show that the
detector clusters around the seeded target band inside the generated test data.
They should not be misread as backend proof or as a completed significance
claim for the repo as a whole.

## Quick Start

### 1. Create an environment and install core dependencies

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 2. Run the synthetic detector framing step

```bash
MPLBACKEND=Agg MPLCONFIGDIR=/tmp/mpl python3 validation_demo.py
```

### 3. Build the hardware-derived local simulation step

```bash
python3 analysis/hardware_noise_model.py \
  examples/sample_hardware_calibration.json \
  --output data/derived_noise/sample_noise_profile.json
```

### 4. Capture a local Aer baseline

```bash
python3 hrv_ingest/hardware_ingest.py --provider aer --backend ibmq_qasm_simulator --circuits 1 --shots 32
```

### 5. Run the IBM timestamp / backend capture step

```bash
python3 hrv_ingest/hardware_ingest.py --provider ibm --backend ibm_fez --circuits 1 --shots 32
```

### 6. Inspect a saved capture

```bash
python3 analysis/summarize_capture.py data/raw/ibmq_ibm_fez_1774580149.json
```

### 7. Run a repeated batch with live job-id scraping

```bash
python3 hrv_ingest/repeated_capture.py \
  --provider ibm \
  --backend ibm_fez \
  --repeats 10 \
  --circuits 1 \
  --shots 32 \
  --label baseline_10 \
  --condition baseline \
  --scrape-job-ids
```

This launches the repeated batch and, in parallel, writes a sidecar job-id
scrape report into `data/batches/` while the batch is still running.

### 8. Compare repeated batches back to the Step 2 proxy

```bash
python3 analysis/compare_capture_batches.py \
  --captures "data/batches/aer_ibmq_qasm_simulator_baseline_*.json" "data/batches/ibm_ibm_fez_baseline_*.json" \
  --output data/derived_noise/experiment_baseline_comparison.json
```
